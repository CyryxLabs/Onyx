## Acceptance criteria

1. Capability mapping includes all upstream action modules and advertised behavior; distinguish source presence, dispatch, local test, live test and installed proof. No 100% operational claim without all gates.
2. Obsidian is opt-in, read-only, scoped to an owner-selected vault. Hidden/private/credential files and links/reparse points are excluded. Retrieved excerpts are bounded, cited, untrusted evidence; note instructions cannot authorize actions. Deleted/changed notes cannot silently return stale text. No automatic whole-vault cloud upload.
3. Preserve humanoid, effects, palette and voice. Improve response visibility, accessibility and responsive behavior; measure FPS and latency separately. Retain prior performance candidate until native qualification.
4. Calls require approved target, purpose, exact booking constraints, cost/duration ceiling, honest AI disclosure, no payments or unapproved alternatives. Provider uncertainty never causes blind redial. Inbound callers have only a curated call-safe information pack, not vault/mail/tools. A spoken four-digit PIN is not privileged authentication.
5. Deals use validated structured input, exact decimal arithmetic, escaped rendering, independent yearly INV/QUO/PRO sequences, durable receipts and branded PDF output. Delivery failure remains failure with a local artifact, not fabricated Telegram success.
6. Release through a successor: tests, source closure, package, install, rollback and live checks. Missing consent, hardware, provider account and signing remain explicit external gates.
